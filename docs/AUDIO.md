## 2. 生成方式

### 2.1 语音（旁白 5 句 + 奶蛙 4 句）

- 走 **Windows.Media.SpeechSynthesis（WinRT / OneCore）**，由 `gen_audio.py` 生成临时
  `.ps1` + jobs JSON 后调用 `powershell.exe` 批量合成，原始产物 16 kHz / 16-bit / 单声道。
- 为什么不用契约里写的 `System.Speech`：本机 `System.Speech`（SAPI5）只暴露
  `Microsoft Huihui Desktop` 与 `Microsoft Zira Desktop` 两个语音，**看不到 Kangkang / Yaoyao**；
  OneCore 层才装着 `Microsoft Kangkang`（男声）、`Microsoft Huihui`、`Microsoft Yaoyao`。
  实测 `SetOutputToWaveFile` 对 Kangkang 直接抛 "No matching voice"。改用 WinRT 后三支中文语音全部可用。
- 语音分配：
  - `vo_01`–`vo_05` → **Kangkang**（低沉男声），SSML `rate="1.20"` → 实测 **1.244x**
  - `frog_voice_1` → Huihui，`frog_voice_2` → Kangkang，`frog_voice_3` → Yaoyao，`frog_voice_4` → Huihui
- **rate 是量化的**（重要，改语速前先看这张表；同一句基准 4.85s）：

  | SSML rate | 实测加速比 |
  |---|---|
  | 0.90 | 0.896x |
  | 0.96 / 1.00 / 1.05 | 1.000x |
  | 1.10 / 1.15 | 1.115x |
  | **1.18 / 1.20 / 1.25 / 1.30** | **1.244x**（旁白用这一档） |
  | 1.40 | 1.386x |
  | 1.50 / "fast" | 1.545x |

  也就是说 1.18–1.22 之间没有精确台阶，1.244x 是最近的一档（偏 +2%）。
- 另一个坑：SSML 的 `pitch` 半音值**必须带正负号**（`0st`/`2st` 直接解析失败 `0x80131537`），
  而且即便写对，本机 OneCore 中文语音也**忽略 pitch**（输出字节数完全不变）。
  所以脚本里 SSML 只传 `rate`/`volume`，**所有变调都交给 numpy 的变速变调**。

### 2.2 numpy 后处理链（`tools/gen_audio.py`）

| 函数 | 作用 |
|---|---|
| `resample(x, ratio)` | 变速变调（磁带式）：ratio>1 升调变短，<1 降调变长 |
| `lowpass / highpass / bandpass` | 级联一阶滤波，用指数 IR + FFT 卷积实现（无 scipy 依赖） |
| `reverb(...)` | 多抽头延迟混响：34 个指数衰减抽头构成稀疏 IR，二次低通柔化，湿声量可调 |
| `echo(...)` | 多抽头回声（拍背/走廊 slapback） |
| `bitcrush(x, bits, hold)` | 比特粉碎 + 采样保持（卡带/数字故障感） |
| `tape_wobble(...)` | 磁带 wow（0.2–1.1 Hz）+ flutter（4–8 Hz）的时变重采样 |
| `saturate(x, drive)` | tanh 软饱和（电子管温暖 / 喉咙毛刺） |
| `loopify(x, xfade)` | 无缝循环：把尾部交叉淡入头部，接缝处**采样级连续** |
| `wrap_tail(buf, total, tail)` | 把循环长度之后的余响折回开头，让混响尾巴跨接缝 |
| `norm(x, -1.5)` | 峰值归一化到 -1.5 dBFS，全轨统一 headroom |

**循环怎么做成无缝的**：音乐/环境先生成"总长 + 余响尾巴"，把尾巴加回开头（`wrap_tail`），
再用 `loopify` 做 50–500 ms 的等功率交叉淡化。接缝两侧的采样差被压到
`|x[0]-x[-1]| ≈ -37 ~ -43 dBFS`（环境 -37、菜单 -39、剧情 -43），远低于可听门限；
心跳/奶蛙叫声直接让首尾落静音，差值 < 1e-5。

### 2.3 程序化音乐（无采样、无 MIDI 文件）

- **音色**：`mb_tone()` = 5 组正弦谐波（1 / 2.004 / 3.02 / 4.37 / 6.24 倍频，故意非整数比制造"金属簧片"），
  各自指数衰减 + 音高随寿命轻微下坠（`drift`）+ 12 ms 铃舌噪声瞬态。
- **调性**：A 小调（Am–F–C–G–Am–F–Dm–E–Am–Am），**整体音准压低 26 音分**
  （剧情轨 32 音分），每个音随机失谐 ±3–4 音分，叠加 `tape_wobble` 做磁带抖晃。
- **"腐坏"细节**：菜单轨第 6 小节在旋律里塞了一个 `G#4`（68 号音，本该是 A），
  音量只有旋律的 1/3，短促——听感上是"音盒卡了一下"。
- **低频不安**：始终铺一层 41.2 / 55 / 55.9 Hz 正弦（55 与 55.9 制造 0.9 Hz 拍频），
  低通 150–170 Hz，随 0.045–0.07 Hz 的极慢 LFO 起伏。

## 3. AI 生成声明

- 全部音频**由程序合成 / 由操作系统内置语音合成**，没有人类演奏、录音或任何第三方素材。
- 语音文本在 `tools/gen_audio.py` 的 `VOICE_JOBS` 与 `VO_TEXTS` 里逐字写死，与契约旁白文本完全一致（现为 5 句）。
- 每段音乐的旋律与和声进行、全部 SFX 的合成参数、奶蛙的四条角色音色，均为本组原创设定（见第 4 节"设计意图"）。
- 脚本、DSP 参数与本文件由 AI 代理撰写；**仓库里没有放入任何版权音频、影视/游戏采样**。
- 说明：AI 无法真正"听"音频。本文档的验收依据是**数值自检**（时长/峰值/RMS/循环接缝/波形相关度），
  主观听感请用 `tools/audio-preview.html` 由人试听；本文件不宣称任何"已由团队试听确认"。

## 5. 关键参数

### 5.1 旁白（vo_01–vo_05，5 句 · 2026-10-29 重录）

1. Kangkang，SSML `rate="1.20"` → **实测 1.244x**（量化台阶，见 2.1），原始 16 kHz。
2. 上采样到 32 kHz → 裁剪前导静音。
3. `resample 0.93`：**再降调约 -1.3 半音**（伴随 +7.5% 时长，像疲惫的老播音）。
   净语速 ≈ 1.244 / 1.075 ≈ **1.16x**，清晰度优先，刻意没有更狠地压。
4. 电话/老广播质感：带通 165–4600 Hz → `tanh(1.5)` 软饱和 → 4.6–5.2 kHz 低通；
   叠一层 -44 dBFS 的 50/100 Hz 电源哼声（跟着语音走）。
5. `echo(115 ms, fb 0.30, mix 0.10)` + `reverb(wet=0.20)`——**湿声 20%，不超过契约的 25%**。
6. 峰值 -1.5 dBFS；**句末追加 0.18 s 数字静音**（本轮按 Lead 要求从 0.30s 收紧；实测可听尾部 ≈ 0.21s，
   落在 0.18–0.22s 要求内；引擎每句后另等 0.68s）。
7. 不含任何背景音乐——引擎自己混。

**剧情时长账（供 Lead 核对）**：

| | 时长 |
|---|---|
| 5 个文件合计 | **22.69 s** |
| + 引擎 5 × 0.68 s 停顿 | 3.40 s |
| **游戏内剧情总时长** | **26.09 s** |

比改动前（6 句 40.67 s + 6 × 0.68 s ≈ 44.8 s）短了约 **18.7 s**。

### 5.2 奶蛙（frog_voice_1–4）

- 目标"3–5 s 且可无缝循环、不刺耳"：四条都落在 3.87–4.27 s，结尾补静音/余响后用 `loopify` 收缝。
- 起始 0.01–0.02 s 淡入、结尾 0.25–0.40 s 淡出，**没有硬切的爆音**（TTS 原声起音也被裁掉）。
- 全部经过 bandpass + `tanh` 软饱和，峰值统一 -1.5 dBFS，RMS 在 -17.6 ~ -24.9 dBFS，
  用于"靠近就放大"的距离衰减时不会突然炸响。
- `frog_voice_2` 的低吼最响（RMS -18.2），`frog_voice_4` 的耳语最轻（RMS -24.9）——
  有意的层次：耳语必须逼玩家靠近才听得见。

### 5.3 SFX

- 全部峰值统一 -1.5 dBFS、**没有一条削波**（全局峰值实测 0.8413 = -1.5 dBFS）。
- 主观响度用 manifest 的 `gain` 分档（0.32 悬停 → 0.90 被抓），引擎再乘总音量即可。
- 金属类（铃、门闩）故意用非整数倍频（2.41x / 3.87x）避免"电子琴"感。

判定条件（任一不过就 `FAIL` 并让脚本以非 0 退出）：

| 检查项 | 阈值 |
|---|---|
| 声道 / 采样率 | 单声道、22050–32000 Hz（本套统一 32000） |
| 峰值 | -3.0 ~ -0.5 dBFS，且线性峰值 < 0.90（绝不削波） |
| 循环接缝 | `abs(x[0]-x[-1]) <= max(0.02, 20 × 中位相邻采样差)` |
| 单文件体积 | < 2.5 MB |

**额外做过的离线校核**（临时脚本，未入库）：

- 语音未被处理链毁掉：把旁白与 TTS 原声按同一条链对齐后，前 2.2 s 波形相关度 **0.92**
  （重失真低吼 0.65，符合预期）。本轮 5 句重录后复测同样在 0.90 以上。
- 谱心：旁白 879–951 Hz、奶蛙 607–3401 Hz（耳语最高，因为砍掉了低频），符合"降调但清晰"的预期。
- 静音占比：旁白 14–31%（本轮短句更紧凑）、奶蛙 15–54%（含尾部留白），无异常整段静音。
- 直流偏移：全部 `abs(dc) < 0.001`。
- 音乐确有音符事件：菜单轨 28.5 s 内检出 ~29 个能量起音，剧情 ~28，环境 ~85（含噪底起伏）。

## 7. 重新生成

```bash
# 全量重建（语音重新合成 + 全部 DSP + 自检 + 重写 manifest）
python tools/gen_audio.py

# 只重建指定轨（不会覆盖 manifest）
python tools/gen_audio.py --only vo_03,vo_04

# 复用临时目录里的 TTS 缓存（%TEMP%/milkfrog_tts/tts_raw）
python tools/gen_audio.py --skip-tts

# 强制重跑 TTS
python tools/gen_audio.py --force-tts
```

- 依赖：Python 3.10+、numpy（本机 2.5.2）；**不需要 ffmpeg、scipy、任何网络**。
- TTS 缓存写在系统临时目录 `%TEMP%/milkfrog_tts/tts_raw`，**不进仓库**；缓存带文本指纹
  （`<key>.json` 记录 SSML hash），改了文本或语速会自动重合成，不会拿旧音频凑数。
- 耗时：TTS ≈ 1–2 s，DSP 全量 ≈ 11 s。
- 试听：`python serve.py 8000` → <http://127.0.0.1:8000/tools/audio-preview.html>

## 9. 引擎接入建议（Lead / src/audio.js 参考）

- 直接按 `manifest.tracks[key]` 取 `file`（相对仓库根）、`gain`、`loop`、`duration`。
- 循环轨用 `HTMLAudioElement.loop = true` 或 `AudioBufferSourceNode.loop = true`；
  采样率统一 32000，WebAudio 会自动重采样，不需要手动处理。
- 奶蛙四条循环会**同时**播放且随距离放大：建议每条 `loop = true`、`playbackRate = 1`，
  距离衰减只改 `gain`（0 → manifest.gain），不要改 `playbackRate`（会破坏已调好的音准）。
- 心跳：`loop = true`，音量在 `0.0 → 0.72` 之间按最近奶蛙距离插值（心跳本身 RMS 只有 -17.9 dBFS，可放心抬高）。
- 旁白五句逐句播放，文件内已有 0.20 s 静音，引擎的 0.68 s 停顿照旧即可。
- SFX 可叠音（`sfx_pickup` 尤其）：用多个 `Audio` 实例或 WebAudio `AudioBufferSourceNode`，
  不要复用同一个 element 打断上一次。

## 10. 已知取舍与限制（照实写）

1. **语速没有精确的 1.18–1.22 档**：WinRT 把 rate 量化成 0.896 / 1.000 / 1.115 / 1.244 / 1.386 / 1.545 六档，
   本轮取 1.244x（离要求偏 +2%）。若觉得偏快，退一档 1.115x 会让 5 条文件合计变成约 25.3 s
   （剧情总时长 ≈ 28.7 s，仍在 26–30 s 区间）——改 `VOICE_JOBS` 里那 5 个 rate 重跑即可。
2. **16 kHz 源**：OneCore TTS 只输出 16 kHz；脚本上采样到 32000 Hz 并做 7.2 kHz 低通。
   语音有效带宽仍在 8 kHz 以内——这对"老旧广播"的设定是加分项，但不是真正的 32 kHz 录音。
3. **没有音高保持式变调**：numpy 里没有相位声码器，`resample` 是变速变调
   （降调同时变慢）。旁白降到 0.93 后净语速约 1.16x，仍在"自然偏快"的范围里。
4. **混响是抽头式，不是卷积房间**：抽头混响在长尾上会有一点"梳状"颜色，
   音乐轨用 0.22 以内的湿声量压住了它。
5. **`amb_game` 23.50 s**（契约写 24s 左右）：0.5 s 循环交叉淡化后的实际长度；
   `music_menu` 28.52 s、`music_story` 29.94 s 同理。
6. **`heartbeat` 1.57 s**（契约 1.5–2 s）：0.03 s 交叉淡化后 1.57 s，双拍间隔 0.29 s。
7. **音乐是单声道**：契约允许音乐立体声，这里为体积与混音简单选择单声道。
8. **`vo_06` 已废弃**：本轮剧情压成 5 句，文件与 manifest key 都已删除。
   若以后要恢复第 6 句，在 `VOICE_JOBS`/`VO_TEXTS` 里加回并重跑即可（旧文本：
   「别停下。它们还记得你的味道。」）。
9. **AI 没能"听"**：所有结论来自数值与波形统计，主观听感仍需人工在试听台过一遍；
   若人耳认为某条太吵/太糊，改对应 `gain`（manifest）或脚本里那一条的参数后 `--only` 重跑。
